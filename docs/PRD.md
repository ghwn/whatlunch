# 점심 추천 앱 PRD (Product Requirements Document)

## 1. 개요

### 1.1 제품명
**WhatLunch** (가칭)

### 1.2 핵심 가치
"오늘 뭐 먹지?" 고민을 **결정 피로 제거**를 통해 해결한다. 사용자에게 선택지를 던지는 것이 아니라, 즉시 실행 가능한 추천을 제공한다.

### 1.3 타겟 사용자
- 점심 메뉴 결정에 피로를 느끼는 직장인/개인
- 혼밥 위주의 개인 사용자

### 1.4 MVP 성공 기준
- 개발자 본인이 매일 실제로 사용하는 앱

---

## 2. 핵심 기능 요구사항

### 2.1 추천 시스템

| 항목 | 요구사항 |
|------|----------|
| 추천 개수 | 1~10개 (슬라이더 조절, 기본값 3) |
| 추천 알고리즘 | 완전 랜덤 (MVP) |
| 재추천 | 결과가 마음에 안 들면 무제한 재추천 가능 |
| 사용자 프로필 | 없음. 그때그때 입맛이 다르므로 프로필 미구축 |
| 필터 | MVP에서는 없음. 데이터 수집 후 추후 고려 |

### 2.2 위치 기반

| 항목 | 요구사항 |
|------|----------|
| 위치 기준 | 현재 GPS 위치 |
| 기본 검색 반경 | 500m |
| 최대 검색 반경 | 1km (슬라이더 조절 가능) |

### 2.3 식당 정보

| 항목 | 요구사항 |
|------|----------|
| 표시 정보 | 미니멀 (식당명 + 거리) |
| 상세 정보 | 네이버지도/카카오맵 외부 링크로 대체 |
| 블로그 후기 | 버튼 클릭 시 네이버 블로그 검색 결과 URL로 이동 |

### 2.4 사용자 플로우
1. 추천 결과 확인
2. 마음에 드는 식당의 [지도] 또는 [블로그 후기] 클릭
3. 블로그 후기 확인 후 결정 완료 (앱 내 별도 액션 불필요)
4. 마음에 안 들면 "다시 추천받기"로 재추천

### 3.3 버튼 동작

| 버튼 | 동작 |
|------|------|
| [지도] | 카카오맵 장소 상세 페이지로 이동 (외부 링크) |
| [블로그 후기] | 네이버 블로그 검색 결과 페이지로 이동 (외부 링크) |
| [다시 추천받기] | 현재 설정(거리, 개수)으로 새로운 랜덤 결과 표시 |

### 3.4 재추천

| 항목 | 내용 |
|------|------|
| 재추천 횟수 제한 | 없음 (무제한) |
| 이전 결과 중복 | 랜덤이므로 이전에 나왔던 식당도 다시 나올 수 있음 |

### 3.5 로딩 화면

- 추천 버튼 클릭 후 API 응답 대기 중 **음식/점심 관련 팁** 표시
- 예시:
  - "점심 후 10분 산책은 소화에 좋아요"
  - "오늘 날씨가 추우니 따뜻한 국물은 어때요?"
  - "새로운 맛집 도전은 화요일이 좋대요"

## 4. 기술 아키텍처

### 4.1 플랫폼
**PWA (Progressive Web App)**
- 스토어 심사 없이 빠른 배포
- 홈 화면 추가로 앱처럼 사용 가능
- 웹 기술로 개발

### 4.2 기술 스택

| 영역 | 기술 | 선정 이유 |
|------|------|----------|
| 프레임워크 | **React 19 (Vite 7)** | React 학습에 최적화, 빠른 개발 서버, 간단한 설정 |
| 패키지 매니저 | **Bun** | 빠른 설치 속도 |
| 스타일링 | **CSS Modules** 또는 **vanilla CSS** | 외부 의존성 없음, CSS 기본기 학습 |
| 지도 | **Kakao Maps SDK** | 카카오 API와 일관성, 한국 데이터 우수 (필수 외부 의존성) |
| 상태관리 | **React useState/useContext** | 외부 라이브러리 없이 React 내장 기능만 사용 |
| HTTP 클라이언트 | **fetch API** | 브라우저 내장, 별도 라이브러리 불필요 |
| 배포 | **자체 서버 (Docker)** | 홈서버에 Docker 컨테이너로 배포 |

### 4.2.1 의존성 최소화 원칙

```
// package.json 예상 의존성
{
  "dependencies": {
    "react": "^19.x",
    "react-dom": "^19.x"
  },
  "devDependencies": {
    "vite": "^7.x",
    "@vitejs/plugin-react": "^4.x"
  }
}
```

외부 라이브러리 없이 React 내장 기능과 브라우저 API만으로 구현한다.

### 4.3 외부 API

| API | 용도 | 비용 |
|-----|------|------|
| **카카오 로컬 API** | 음식점 검색 (키워드, 카테고리, 위치 기반) | 무료 (일 30만 건) |
| **네이버 블로그 검색** | URL 생성만 (API 호출 없음) | 무료 |
| **카카오맵 SDK** | 현재 위치 표시용 미니맵 | 무료 |

### 4.4 데이터 흐름

```
[사용자 GPS]
    ↓
[카카오 로컬 API 호출]
- 카테고리: 음식점 (FD6)
- 반경: 사용자 설정값
- x, y: 현재 좌표
    ↓
[응답에서 랜덤 N개 선택]
    ↓
[결과 표시]
- 식당명
- 거리
- 카카오맵 링크
- 네이버 블로그 검색 URL
    ↓
[사용자 선택]
├─ [지도] 클릭 → 카카오맵 이동
├─ [블로그 후기] 클릭 → 네이버 블로그 검색 이동 → 결정 완료
└─ [다시 추천받기] → 새로운 랜덤 결과 (반복)
```

## 5. 비기능 요구사항

### 5.1 성능
- 추천 결과 표시까지 2초 이내
- 재추천 시에도 동일한 응답 속도 유지
- Lighthouse PWA 점수 90점 이상

### 5.2 오프라인
- 지원 안 함. 온라인 필수.
- 오프라인 시 안내 메시지 표시

### 5.3 인증
- 없음. 로그인 불필요
- 모든 데이터는 로컬 스토리지에 저장 (설정값)

### 5.4 브라우저 지원
- Chrome, Safari (모바일 우선)
- PWA 설치 지원 브라우저

## 6. MVP 범위

### 6.1 포함 (In Scope)

- [x] GPS 기반 현재 위치 파악
- [x] 카카오 로컬 API로 주변 음식점 검색
- [x] 랜덤 추천 (1~10개, 기본 3개)
- [x] 거리 설정 (500m~1km 슬라이더)
- [x] 결과 카드 (식당명, 거리)
- [x] 무제한 재추천 기능
- [x] 카카오맵 장소 페이지 연결
- [x] 네이버 블로그 검색 URL 연결
- [x] 로딩 중 팁 표시
- [x] PWA 설치 지원

### 6.2 제외 (Out of Scope)

- [ ] 사용자 프로필/취향 학습
- [ ] 필터 (카테고리, 가격대 등)
- [ ] 방문 기록/히스토리
- [ ] 그룹 점심 지원
- [ ] 오프라인 모드
- [ ] 로그인/회원가입
- [ ] 블로그 내용 분석
- [ ] 앱 내 "결정" 확인 액션

## 7. 향후 확장 고려사항

MVP 이후 데이터 수집 결과에 따라 검토:

1. **필터 기능**: 카테고리(한식/중식/일식), 가격대
2. **방문 기록**: 최근 선택 기록, 주간 로테이션
3. **스마트 추천**: 시간대, 날씨 기반 추천
4. **스마트 재추천**: 이전에 본 식당은 해당 세션에서 제외
5. **공유 기능**: 카톡으로 결과 공유

## 8. 리스크 및 대응

| 리스크 | 영향 | 대응 방안 |
|--------|------|-----------|
| 카카오 API 제한 초과 | 서비스 중단 | 개인 사용 목적이라 30만 건/일 충분. 재추천 시에도 문제없음 |
| GPS 정확도 낮음 (실내) | 잘못된 결과 | 수동 위치 조정 기능 추후 추가 고려 |
| 폐업 식당 추천 | 사용자 불만 | 카카오 데이터 신뢰, 블로그 후기에서 확인 가능 |
| 재추천 남용 | API 호출 증가 | 개인 사용이라 영향 미미 |

## 9. 용어 정의

| 용어 | 정의 |
|------|------|
| 결정 피로 | 선택지가 많아 결정하기 어려운 심리적 상태 |
| PWA | Progressive Web App. 웹 기술로 만든 앱 |
| 카카오 로컬 API | 카카오에서 제공하는 장소 검색 API |
| 재추천 | 현재 결과가 마음에 안 들 때 새로운 랜덤 결과를 요청하는 기능 |

## 부록: API 및 URL 예시

### 카카오 로컬 API 요청
```
GET /v2/local/search/category.json
?category_group_code=FD6
&x=127.0276
&y=37.4979
&radius=500
```

### 카카오 로컬 API 응답 (일부)
```json
{
  "documents": [
    {
      "place_name": "서북면옥",
      "distance": "320",
      "place_url": "http://place.map.kakao.com/12345",
      "x": "127.0280",
      "y": "37.4985"
    }
  ]
}
```

### 네이버 블로그 검색 URL 생성
```
https://search.naver.com/search.naver?ssc=tab.blog.all&sm=tab_jum&query={encodeURIComponent(식당명)}
```

**예시:**
```
https://search.naver.com/search.naver?ssc=tab.blog.all&sm=tab_jum&query=%EC%84%9C%EB%B6%81%EB%A9%B4%EC%98%A5
```
